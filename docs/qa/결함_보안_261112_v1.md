# 아이콘 빌더 보안 점검 결과 (v1, 2026-11-12)

## 요약

- 대상: 정적 프론트엔드 `app/`(GitHub Pages 공개 배포 예정), `supabase/schema.sql`(익명 로그인 전제), Edge Function `supabase/functions/generate-icon/index.ts`
- 방법: 코드 리뷰와 동작 확인을 함께 했습니다. 동작 확인은 로컬 http://localhost:8765/ 에서 Playwright(Chromium)로 했습니다. 실제 Supabase 프로젝트에는 연결하지 않았습니다. RLS와 Edge Function은 코드로 판정했고, 공격자가 REST로 직접 넣는 행은 IndexedDB에 같은 행을 넣어 흉내 냈습니다.

### 문제없이 통과한 항목

- 화면 XSS: 키워드, 설명, 이름, 사이트 이름, 검색 주소에 페이로드 `"><img src=x onerror=alert(1)><svg/onload=…><script>…` 를 넣어 봤습니다. 후보, 보관함, 참고 링크, 사이트 표 어디에서도 실행되지 않았습니다. dialog 0건, `window.__pwn` 미설정. 모든 출력이 `esc()`로 이스케이프됩니다.
- 악성 SVG 업로드: script, onload, foreignObject+onerror, 외부 image/use/@import, `javascript:` 링크를 넣은 SVG를 미리보기와 생성에 써 봤습니다. 실행 0건, 외부 요청 0건. 모든 SVG를 `<img src="data:…">`로 그리므로 스크립트와 외부 리소스가 차단됩니다.
- URL 검증: `javascript:`, `JaVaScRiPt:…//https://`, `data:text/html`, 앞 공백이 붙은 `javascript:`는 모두 거부됩니다(화면 + DB `check` 2중).
- 하드코딩된 비밀값 없음: `config.js`는 비어 있고 ANTHROPIC_API_KEY는 `Deno.env`로만 읽습니다. localStorage에는 설정(공개 키)과 `sitesSeeded` 플래그만 저장됩니다.
- service_role 차단: `sb_secret_…`, `SB_SECRET_…`, role=service_role JWT는 저장이 거부됩니다(우회 방법은 S-11 참고).
- icons RLS: update 정책이 없어 수정할 수 없고, 삭제는 `owner = auth.uid()`일 때만 됩니다. insert는 owner를 위조할 수 없습니다.
- 스토리지: 업로드와 삭제는 자기 폴더(`<uid>/`)로 제한됩니다. select 정책이 없어 목록 조회도 안 됩니다. 버킷 MIME에 SVG가 빠져 있어 공개 도메인을 통한 SVG XSS가 막혀 있습니다.
- Edge Function 오류 응답: `generation failed`, `요청을 처리할 수 없습니다.`처럼 일반 문구만 돌려주며 스택이나 키는 노출하지 않습니다.

## 재현에 쓴 페이로드(요약)

- 텍스트: `"><img src=x onerror=alert('xss1')><svg/onload=alert('xss2')>'`<script>alert(3)</script>`
- 악성 SVG: `<svg onload=…>` + `<script>` + `<foreignObject><img onerror>` + `<image href=외부>` + `<use xlink:href=외부>` + `<a href="javascript:">` + `<style>@import url(외부)`
